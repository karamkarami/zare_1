# ضریب بهبود (Improvement Factor) کنسلر سه‌پالسی روی داده خام

این پوشه مستقل از بقیه پروژه است و دو فایل دارد:

| فایل | کار |
|---|---|
| `main_if.m` | اسکریپت اصلی: داده را می‌خواند، کلاتر را خودش پیدا می‌کند و IF را حساب می‌کند |
| `if_demo_data.m` | داده خام ساختگی برای امتحان کردن اسکریپت: کلاتر با IF معلوم (39.1 dB)، یک هدف متحرک و یک هدف تست ثابت در سلول 1000 (یک حلقه روی PPI، با IF برابر 70 dB) |

## اجرا

1. در بخش `Settings` بالای `main_if.m`، مسیر فایل را در `dataFile` بنویسید. اگر خالی بماند، داده دمو اجرا می‌شود.
2. داده باید ماتریس مختلط باشد: **هر سطر یک PRI و هر ستون یک سلول برد**. اگر برعکس است، `pulsesInRows = false` بگذارید.
3. `main_if` را اجرا کنید.

| تنظیم | پیش‌فرض | معنی |
|---|---|---|
| `dataVar` | `''` | نام متغیر داخل فایل. اگر خالی باشد، بزرگ‌ترین متغیر عددی برداشته می‌شود |
| `pris` | `[]` | PRIهایی که استفاده می‌شوند، مثلا `1:300` |
| `firstCell` | `1` | اولین سلول برد. نشتی فرستنده و blanking اول برد را کنار می‌گذارد |
| `clutterCells` | `[]` | محدوده کلاتر، هر سطر یک `[اول آخر]`، مثلا `[1 400]`. اگر خالی باشد، در کل برد جستجو می‌شود |
| `skipCells` | `[]` | سلول‌هایی که کلاتر نیستند، مثلا هدف تست: `[990 1110]` |
| `decoderTaps` | `[]` | اختیاری: ضرایب دیکدر در راستای برد. به‌طور پیش‌فرض داده خام استفاده می‌شود |
| `priStep` | `1` | اگر دو پالس یک‌درمیان (PRI به PRI) عوض می‌شوند، `2` بگذارید |
| `minCnrDb` | `20` | سلول کلاتر دست‌کم این مقدار بالاتر از نویز است |
| `maxDoppler` | `0.05` | داپلر میانگین سلول کلاتر کمتر از این کسر از PRF است |
| `outlierDb` | `10` | سلولی که IFش این مقدار پایین‌تر از میانه باشد کنار گذاشته می‌شود (هدف متحرک داخل کلاتر) |

## روش

1. **نویز:** میانگین توان هر سلول برد حساب می‌شود. آرام‌ترین سلول‌ها فقط نویز دارند. نویز برابر میانه سلول‌هایی است که حداکثر 1.8 dB بالاتر از صدک دهم هستند. DC offset گیرنده هم از همین سلول‌ها تخمین زده و کم می‌شود.
2. **پیدا کردن کلاتر:** سلولی کلاتر است که CNR آن از `minCnrDb` بیشتر باشد و داپلر میانگینش (pulse pair) نزدیک صفر باشد. جستجو فقط داخل `clutterCells` و بیرون از `skipCells` انجام می‌شود. سلول‌هایی که هدف متحرک دارند (هواپیما، ماشین، پرنده) کنار گذاشته می‌شوند.
3. **کنسلر:** خروجی کنسلر `y(m) = x(m) - 2x(m-1) + x(m-2)` است.
4. **ضریب بهبود:**

```
Cin  = Pin  - N          توان کلاتر ورودی
Cout = Pout - 6N         کلاتر باقی‌مانده در خروجی (بهره نویز کنسلر 1+4+1 = 6 است)
CA   = ΣCin / ΣCout      تضعیف کلاتر
IF   = 6 · CA            یعنی IF = CA + 7.8 dB
```

عدد 6 میانگین بهره کنسلر برای هدف‌ها روی همه داپلرهاست. برای همین `IF = (S/C)out / (S/C)in = 6·Cin/Cout` است. مقدار `6·ΣPin/ΣPout` (بدون کم کردن نویز) هم چاپ می‌شود که همیشه یک کران پایین برای IF است.

خروجی‌ها: جدول قطعه‌های کلاتر، IF کل، میانه IF تک‌تک سلول‌ها و چهار نمودار. نمودارها تصویر داده، توان هر سلول قبل و بعد از کنسلر، IF هر سلول و طیف داپلر کلاتر همراه با پاسخ کنسلر را نشان می‌دهند.

## انتخاب سلول‌های کلاتر (مهم)

مقایسه توان ورودی و خروجی کنسلر دقیقا همان تعریف IF است. ولی عددی که به دست می‌آید فقط به سلول‌هایی بستگی دارد که «کلاتر» حساب شده‌اند. اسکریپت هر پژواک قوی با داپلر نزدیک صفر را کلاتر می‌داند. پس این‌ها هم از نظر اسکریپت کلاتر هستند:

* هدف تستی که در همه PRIها در یک برد ثابت گذاشته شده (حلقه روی PPI)
* delay line
* نشتی فرستنده

IF کل با توان وزن داده می‌شود (`ΣCin / ΣCout`). برای همین قوی‌ترین پژواک عدد کل را تعیین می‌کند. یک هدف تست ثابت و خیلی قوی معمولا خیلی پایدارتر از کلاتر واقعی است و IF کل را بالا می‌برد. چون هر PRI دو پالس دارد، هدف تست در داده خام دو بار دیده می‌شود: یک پژواک از پالس کوتاه و یک پژواک از پالس بلند.

برای دیدن این اثر، اسکریپت یک جدول از **قطعه‌های کلاتر** چاپ می‌کند. هر قطعه یک گروه سلول کلاتر پشت سر هم است. برای هر قطعه، برد، بیشترین CNR، سهم از توان کلاتر و IF آن قطعه نوشته می‌شود. روی داده دمو:

```
     cells        max CNR   power share      IF
   1043 - 1106    79.9 dB      79.7 %       69.8 dB    <- هدف تست، پژواک پالس بلند
   1000 - 1012    79.9 dB      16.2 %       69.7 dB    <- هدف تست، پژواک پالس کوتاه
      1 - 299     66.1 dB       4.1 %       38.9 dB    <- کلاتر زمین
```

| تنظیم | IF کل |
|---|---|
| بدون محدودیت (هدف تست هم کلاتر حساب شده) | 52.6 dB |
| `skipCells = [990 1110]` | 38.9 dB |
| `clutterCells = [1 800]` | 38.9 dB |
| مقدار واقعی کلاتر | 39.1 dB |

اگر IF کل خیلی بالاتر از میانه IF سلول‌ها باشد، اسکریپت قطعه‌ای را که عدد را تعیین کرده نام می‌برد. سلول‌هایی را هم که خیلی پایدارتر از بقیه هستند جدا گزارش می‌دهد.

IF هدف تست هم معنی دارد، ولی معنی دیگری دارد. این عدد پایداری مسیری است که سیگنال تست از آن عبور می‌کند، نه IF روی کلاتر. اگر سیگنال تست از RF و با اسیلاتورهای خود رادار تزریق شود، عدد آن سقف پایداری گیرنده و اسیلاتورهاست. ناپایداری فرستنده، حرکت کلاتر و مدولاسیون چرخش آنتن در این عدد نیستند. اگر هدف تست بعد از ADC و به‌صورت دیجیتال اضافه شود، IF آن فقط به نویز محدود است و چیزی درباره سیستم نمی‌گوید.

## دیکدر لازم است؟

**نه.** دیکدر در راستای برد (fast time) فیلتر می‌کند و کنسلر در راستای پالس‌ها (slow time). هر دو خطی و تغییرناپذیر با زمان‌اند و روی دو بعد جدا کار می‌کنند. پس ترتیبشان مهم نیست:

```
canceler(decoder(X)) = decoder(canceler(X))
```

یعنی کنسلر سه‌پالسی را می‌شود مستقیم روی داده خام اعمال کرد. ضریب بهبود به پایداری پالس به پالس کلاتر بستگی دارد (حرکت کلاتر، نویز فاز اسیلاتور، ناپایداری فرستنده و jitter زمانی). این پایداری با دیکدر عوض نمی‌شود. روی داده دمو، که هر PRI هر دو پالس را دارد (Barker 13 و کد 64 چیپی)، با `clutterCells = [1 800]`:

| پردازش | IF اندازه‌گیری‌شده |
|---|---|
| داده خام | 38.9 dB |
| بعد از دیکدر پالس بلند | 38.7 dB |
| بعد از دیکدر پالس کوتاه | 38.9 dB |
| مقدار واقعی | 39.1 dB |

اختلاف دو ترتیب (دیکدر بعد کنسلر و برعکس) در حد دقت عددی است (`5e-15`).

### شرط‌ها و دام‌ها (اسکریپت همه را چک می‌کند)

* **اشباع ADC:** اگر کلاتر نزدیک ADC را اشباع کند، سیستم قبل از هر پردازش دیجیتال غیرخطی شده است. در این حالت ترتیب پردازش هم کمکی نمی‌کند و IF محدود می‌شود. اسکریپت نمونه‌هایی را که دقیقا روی بیشترین (یا کمترین) مقدار جمع شده‌اند می‌شمارد و هشدار می‌دهد.
* **پالس‌های یک‌درمیان:** دیکدر و کنسلر فقط وقتی جابه‌جاپذیرند که شکل موج همه PRIها یکی باشد. اگر دو پالس PRI به PRI عوض شوند، کنسلر باید PRIهای هم‌نوع را از هم کم کند (`priStep = 2`). اسکریپت همبستگی lag 1 و lag 2 را چاپ می‌کند. اگر lag 2 خیلی بیشتر از lag 1 باشد، هشدار می‌دهد.
* **نشتی فرستنده در اول برد:** نشتی خیلی پایدار است و IF را بیش از واقع خوب نشان می‌دهد. در دمو، 20 سلول نشتی IF کلاتر نزدیک را از 38.9 به 42.7 dB رساند. اسکریپت سلول‌هایی را که خیلی پایدارتر از بقیه هستند گزارش می‌دهد. `firstCell` را بعد از آن‌ها بگذارید.
* **نویز:** IF اندازه‌گیری‌شده نمی‌تواند از CNR کلاتر بیشتر شود. اگر کلاتر باقی‌مانده زیر نویز باشد، فقط کران پایین چاپ می‌شود.

### دیکدر کجا کمک می‌کند؟

فقط وقتی که IF به نویز محدود شده باشد. دیکدر CNR کلاتر **نقطه‌ای** (ساختمان، دکل) را به اندازه بهره فشرده‌سازی بالا می‌برد و سقف IF قابل اندازه‌گیری را بالاتر می‌برد. برای کلاتر **گسترده**، CNR بعد از دیکدر تقریبا همان می‌ماند. دیکدر کلاتر را در برد هم جمع می‌کند، پس محل کلاتر روی نمودار دقیق‌تر دیده می‌شود. برای امتحان روی دمو:

```matlab
[~, dd] = if_demo_data();  decoderTaps = conj(fliplr(dd.long));
```

اسکریپت در MATLAB R2016b به بعد اجرا می‌شود و به هیچ toolboxی نیاز ندارد. در GNU Octave هم اجرا می‌شود.
